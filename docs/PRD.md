# LqCompare 产品说明

> 条目级的规格在 [PRD-actions.md](PRD-actions.md)（369 条）。本文只讲**定位、范围与取舍**。

## 1. 定位

LqCompare 是一个**文件与文件夹比对工具**：比较两个文件或两个目录树的差异，
看懂差异，并把差异按需要搬过去（复制、同步、合并、打补丁）。

它面向的场景是**工程与运维的日常核对**：

- 两份配置/源码/固件镜像之间到底差在哪；
- 一个目录从 A 版本到 B 版本多了什么、少了什么；
- 两棵目录树该往哪个方向同步，同步会删掉什么；
- 三方合并时该保留哪一侧，哪些是真正的冲突；
- 一批可执行文件的版本号是否回退了。

## 2. 对标与取舍

| 维度 | 依据 |
| --- | --- |
| 功能面 | **Beyond Compare 5**（Standard + Pro 的全部会话类型与命令） |
| 界面形态 | **Ribbon 多页面**（TortoiseGitMerge 只有 1 个 Tab，是反面教材） |
| 交互参考 | TortoiseGit 的比对/合并窗口与客户端入口（日志、修订图、Blame） |
| 冲突裁决 | 两者行为冲突时 **以 Beyond Compare 为准** |

测绘细节见 [research/](research/)：
Beyond Compare 38 个功能域 / 1682 个功能点，TortoiseGit 1166 个功能点。

## 3. 范围

### 3.1 做（13 种会话类型）

| 类别 | 会话类型 | 说明 |
| --- | --- | --- |
| 文本 | 文本比较、文本合并（三路）、文本编辑、文本补丁 | 行对齐、忽略规则、字符级差异、编辑与保存、补丁生成与应用 |
| 文件夹 | 文件夹比较、文件夹同步、文件夹合并（三路） | 扫描、快速测试、内容比对、状态判定、复制/移动/删除/重命名、镜像、同步预览、逐条合并 |
| 数据 | 表格比较、十六进制比较、图片比较、媒体比较 | 单元格/字节/像素/标签四个层次的对照 |
| 系统 | 注册表比较、版本比较、压缩包比较 | 平台相关能力；注册表与版本资源限 Windows |

横切能力：会话管理与 Home 视图、过滤器与文件格式定义、报表与打印、快照、
版本控制集成（Git）、命令行与脚本、选项与外观、国际化。

### 3.2 有意不做或降级

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 完整的 Git 客户端 | **不做** | 本工具只做「比较与合并」。提交、推送、变基交给用户熟悉的工具；我们提供 `git difftool` / `mergetool` 的配置片段 |
| 远程连接（FTP/SFTP/云存储） | **降级为后续** | 先把本地文件系统做到扎实；远程数据源依赖凭据管理与大量异常路径，放在后面批次 |
| 音频波形逐样本比对 | **不做** | 媒体比对只比标签与元数据（与 Beyond Compare 一致），波形只作为人工听辨的辅助概览 |
| 注册表写操作的默认放开 | **禁止** | 写实时注册表默认只允许 HKCU，HKLM 需显式解锁；每次写操作必须先导出 .reg 备份 |
| 引入 GPL/AGPL 组件 | **禁止** | 面向闭源商用；LGPL 组件（Qt）以动态链接使用 |

## 4. 设计原则（会直接影响实现方式）

| 原则 | 具体含义 |
| --- | --- |
| **破坏性操作必须可逆或明确告知不可逆** | 删除默认走回收站；覆盖前先备份；跨卷移动、永久删除在操作前明说不可撤销；批量操作强制预演 + 二次确认 |
| **过滤不能掩盖风险** | 被显示过滤器隐藏的条目，在批量操作中必须显式询问是否包含，不允许静默包含或静默排除 |
| **未知不等于相同** | 未做内容比对时状态是「未知」而不是「相同」；无权限读取的注册表项是「不可读」而不是「不存在」 |
| **结论必须可解释** | 每个条目能回答「为什么是这个状态」（用了哪几条比较准则、结果如何）；报表头部记录比较准则与忽略规则，保证结论可复现 |
| **界面骨架先于行为** | 未实现的命令保留按钮并标注 ACTION-ID，而不是隐藏——这样功能面一眼可见，进度也可核对 |
| **界面不直接连业务** | 一切命令经命令注册中心，同一命令在多入口的启用状态必然一致 |

## 5. 平台与交付

| 项 | 取值 |
| --- | --- |
| Qt / 语言 | Qt 5.15.2 / C++17（构建期 `error()` 强制） |
| 构建 | qmake，按模块以 `.pri` 组织 |
| 交付目标 | Windows MinGW 8.1.0 32 位 |
| 开发与测试 | macOS clang_64、Linux |
| 界面库 | LqRibbon（与 Ailecium 共用） |
| 用户配置 | 标准模式存用户配置目录；便携模式（程序目录放 `lqcompare.portable` 标记）存程序目录 |
| 凭据 | 存系统凭据库（Windows Credential Manager / macOS Keychain），配置文件中只保留引用标识 |

## 6. 质量门槛

一个条目算完成，必须满足 [development/parallel-workstreams.md](development/parallel-workstreams.md) §4 的准入要求：
完成标准逐条成立、有测试、offscreen 可跑、破坏性路径有预演或备份、不破坏分层、
提交消息带 ACTION-ID 与 issue 号。

仓库级护栏（CI 每次提交都跑）：

| 检查 | 拦住什么 |
| --- | --- |
| `tools/check_layering.py` | 「加一行 include」把 Services 层变成界面依赖，导致服务层不再可测 |
| `tools/check_icons.py` | 图标声明/引用/文件三者不一致；孤立图标诱导形成第二套视觉语言 |
| `tools/check_spec.py` | 规格数据不合法；有人手改了 PRD 生成物；交付产物被 git 跟踪 |
