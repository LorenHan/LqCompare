# 同类开源实现参考

> 本目录的两份测绘文档（Beyond Compare / TortoiseGit）回答的是「**要做什么**」；
> 本文回答的是「**别人怎么做的**」，用于避免在算法、数据结构和测试方法上重复踩坑。
>
> 结论一句话：**可以读，不可以抄。** 四个参考实现全部是 GPL，它们的代码一行都不能
> 进入本仓库（闭源商用方向，见 ENG-013）。本文记录的全是设计与方法层面的借鉴。

## 1. 许可证结论（先看这节）

| 项目 | 技术栈 | 许可证 | 可否复用代码 |
| --- | --- | --- | --- |
| [KDE/kdiff3](https://github.com/KDE/kdiff3) | C++ / Qt | **GPL-2.0** | ❌ 不可 |
| [WinMerge/winmerge](https://github.com/WinMerge/winmerge) | C++ / MFC（Windows） | **GPL-2.0** | ❌ 不可 |
| [GNOME/meld](https://gitlab.gnome.org/GNOME/meld) | Python / GTK | **GPL-2.0** | ❌ 不可 |
| FreeFileSync | C++ / wxWidgets | 官方不在 GitHub，**许可证未核实** | ❌ 不可 |

三条硬约束：

1. **GPL 的传染性不因「只抄一个函数」而减弱。** 判定不看抄了多少行，看是否构成
   受版权保护的表达。因此本仓库不引入它们的任何源码文件，也不做「改改变量名」这类搬运。
2. **算法本身不受版权保护，实现受保护。** 因此「用 Myers 做行级差异」可以自己写，
   但不能照搬 kdiff3 里从 GNU diff 移植的那份实现（`src/gnudiff_*`）。
3. **连测试语料都要注意。** kdiff3 的 `test/testdata/` 是 GPL 项目的一部分，
   不把它的文件拷进来；我们照抄的是**命名约定**（约定不是受版权保护的表达）。

如果将来想复用某个实现的代码，唯一可行路径是把它做成独立进程/动态库并以 GPL 分发，
这与本产品闭源商用的定位冲突，因此不作为选项。

## 2. kdiff3：最值得读的一个

它是四个里唯一「C++ + Qt + 同时做文件与目录比对 + 有独立可测的差异引擎」的实现，
与本项目的技术栈和目标最接近。

### 2.1 差异引擎与界面是分开的

`src/diff.h` 定义的是**数据结构**（差异列表、三方对齐行列表），不是函数集合；
界面（`difftextwindow.cpp`）只是这些数据的渲染器。带来的直接后果是：
**差异引擎可以在没有窗口、没有文件系统的情况下被测试。**

对照我们的分层铁律，这相当于把差异引擎放进 `Services`，且它的输入是内存中的行数据。
`ENG-001`（分层）与 `TXT-001`（对齐算法）应共同保证这一点：引擎不得 include 任何界面头。

### 2.2 把「期望的对齐」编码成数据

`test/testdata/README` 里的约定值得直接借用。每个用例四个文件：

```
N_<用例名>_base.txt
N_<用例名>_contrib1.txt
N_<用例名>_contrib2.txt
N_<用例名>_expected_result.txt      # 期望的纵向对齐
```

`_expected_result.txt` 的每一行是**三个行号**（来自 A / B / C），`-1` 表示该侧
在这一显示行上没有对应内容：

```
1 -1 -1        # A 的第 1 行单独占一行，B、C 在此处为空
2 -1  1        # A 的第 2 行与 C 的第 1 行对齐，B 为空
```

这个约定有三个好处，正是我们需要的：

- **对齐结果可被人眼核对**，而不是埋在断言代码里——对齐错了能直接看出错在哪一行。
- **新增用例不用写代码**，丢四个文件进去即可；测试按文件名自动发现并按字母序执行。
- **三方合并（`MRG-018`）与文本对齐（`TXT-038`）可以共用同一套语料格式**。

我们要做的改进：kdiff3 的语料是手工累积的，它另有
`generate_testdata_from_permutations.py` 用 5 行基础文本枚举增删组合来**生成**语料。
两者结合才是完整方案——手写代表性用例 + 生成穷尽性用例。

### 2.3 让引擎可在测试中绕开翻译与配置

`test/alignmenttest.cpp` 开头有两行很说明问题：

```cpp
#define i18n(s) s                    // 测试里把翻译宏退化成恒等
std::unique_ptr<Options> gOptions = nullptr;   // 全局配置置空
```

即：引擎在测试里不应该依赖翻译基础设施和全局单例配置。这对我们是明确的设计要求——
引擎需要配置时**按参数传入**，不要读全局单例，否则测试必须先搭好整套应用环境。

### 2.4 明确不学的部分

- 它从 GNU diff 移植了 Myers 实现（`gnudiff_analyze.cpp` 等，GPL 来源）——我们另写。
- 它的界面是经典 KDE 菜单 + 工具条，与我们的 Ribbon 形态无关。
- 它只有 27 个源码文件规模的单体窗口，没有会话/视图的插件化分层——我们有更细的分层。

## 3. WinMerge：文件夹比对与 Windows 集成的素材

C++ / MFC，仅 Windows，9.2k star，是「文件夹比对」这一侧最成熟的参考。

值得看的：

- **文件夹比对的两侧树视图 + 平铺视图切换**，以及按状态着色的口径
  （左独有 / 右独有 / 不同 / 相同 / 有差异但内容相同）。这与 `DIR-011`（状态判定）
  和 `DIR-012`（着色）直接对应。
- **筛选器的可视化编辑**（把命令行式掩码变成可点选的规则列表）——对应 `FILT-*`。
- **对 Windows 长路径与大小写不敏感文件系统的处理**，这类坑只有在 Windows 上大规模
  使用过才会暴露——对应 `PLAT-*` 与 `DIR-005`（文件名大小写）。

明确不学：MFC 的技术栈、它的界面形态（经典菜单 + 工具条），以及它的 GPL 代码。

## 4. meld：三方合并的交互参考

Python / GTK，Linux 桌面为主。定位与我们的三方合并（`MRG-*`）重合。

值得看的：

- **三方合并的三栏布局与冲突标记呈现**，以及「哪一栏是祖先」的视觉表达
  ——对应 `MRG-002`（祖先栏）。
- **把一个冲突块的决策做成一次点击**（取左 / 取右 / 取两者 / 手工编辑），
  以及决策之后如何回退——对应 `MRG-005`（块决策）与 `MRG-014`（决策日志与撤销）。

明确不学：GTK 技术栈与 Python 实现；它的界面是 GTK 风格，与 Ribbon 无关。

## 6. 本地取用方式

参考实现只用于**阅读**，不进入本仓库，也不需要参与构建：

```bash
mkdir -p ../_references && cd ../_references
git clone --depth 1 https://github.com/KDE/kdiff3.git          kdiff3
git clone --depth 1 https://github.com/WinMerge/winmerge.git   winmerge
git clone --depth 1 https://gitlab.gnome.org/GNOME/meld.git    meld
```

`_references/` 在本仓库之外，不会被提交。若需要长期保留，建议放在工作区同级目录而不是
仓库内，避免有人误把 GPL 源码提交进来。
